## Key Question 1 — Per-vendor capabilities: connectors (Exchange, SharePoint, SMB file shares, Google Drive), incremental sync, permission trimming, custom metadata/filtering, hybrid search, human UI, API/MCP access

### Takeaway
Only a handful of the horizontal options cover all three legacy sources a law firm cares about (Exchange mailboxes, SharePoint, on-prem SMB shares) with permission trimming: Microsoft 365 natively (SharePoint/Exchange; file shares only via a Graph/Copilot connector), Glean (Exchange Online + SharePoint; file-share coverage unconfirmed), Elastic's connector framework (SharePoint Online, Outlook, Network Drive, Google Drive, all with document-level security), Amazon Quick/Q Business (Exchange + SharePoint; SMB unconfirmed) and Coveo (permission replication model). Pure vector/RAG APIs (Pinecone, Vectara, Ragie, LlamaCloud, Unstructured) and Azure AI Search are developer platforms: you bring your own connectors, permission model and UI.

### Cited Findings

**Microsoft 365 (SharePoint + Microsoft Search + Copilot + Graph/Copilot connectors)**
- Microsoft Graph (Copilot) connectors give a tenant up to 50 million items of total index quota at no additional cost; the per-connection default limit is 5 million items, with higher counts requiring a request to Microsoft — [Microsoft Learn: connecting-external-content-api-limits](https://learn.microsoft.com/graph/connecting-external-content-api-limits); [MC865187 (50M backfill announcement)](https://mc.merill.net/message/MC865187)
- Each item appears as a unique citation in Copilot responses and as a distinct Microsoft Search result; update frequency does not consume quota; preview connectors don't count until GA — [Microsoft Learn](https://learn.microsoft.com/graph/connecting-external-content-api-limits)
- Connector schema allows up to 128 properties per connection (custom metadata fields) — [Microsoft Learn](https://learn.microsoft.com/graph/connecting-external-content-api-limits)
- Microsoft 365 Copilot only surfaces organizational data the user has at least view permission to; law-firm permissions are layered (site/library/document) and drift over time — [Kraft Kennedy](https://www.kraftkennedy.com/copilot-isnt-broken-its-being-literal-monitoring-and-troubleshooting-microsoft-copilot-in-legal/); [copilotconsulting.com case study (vendor)](https://copilotconsulting.com/case-studies/legal-amlaw-firm)
- Copilot Retrieval API (for agents): with pay-as-you-go enabled, non-Copilot-licensed users can retrieve from tenant-level sources (SharePoint and Copilot connectors), but per-user data such as OneDrive stays unavailable to them; billed per API call via a linked Azure subscription; still labelled preview — [Microsoft Learn: paygo-retrieval](https://learn.microsoft.com/microsoft-365/copilot/extensibility/api/ai-services/retrieval/paygo-retrieval); [MC1222980](https://mc.merill.net/message/MC1222980); [PAYG terms](https://learn.microsoft.com/en-us/legal/m365-retrieval-paygo-tou/paygo-retrieval-terms); [Retrieval API overview](https://learn.microsoft.com/microsoft-365/copilot/extensibility/api/ai-services/retrieval/overview)
- Copilot Studio SharePoint knowledge limits (official quotas page): files up to 512 MB (split files > 7 MB recommended); each SharePoint source up to 1,000 files, 50 folders, 10 subfolder levels; max 25 SharePoint site URLs per agent with generative orchestration; 15 lists per add-knowledge session; list views not usable; sync frequency 4–6 hours; "metadata filtering at the folder or knowledge source level isn't supported"; column-metadata queries (e.g. list files by column value), file counts, and queries naming a specific file are unsupported; files up to 200 MB require a Microsoft 365 Copilot licence in-tenant with Work IQ enabled — [Microsoft Learn: Copilot Studio requirements & quotas](https://learn.microsoft.com/microsoft-copilot-studio/requirements-quotas)
- Third-party testing reports Copilot Studio silently truncates when quantity limits are exceeded and that Microsoft suggests ~36,000 characters per file for good retrieval quality (third-party, unverified) — [Nordflux](https://nordflux.de/en/insights/copilot-studio-the-real-limits-of-sharepoint-knowledge-sources)
- SharePoint search schema limits: 100 crawled→managed property mappings per managed property; 1,000 values per multi-valued managed property per document; sortable/refinable managed property size 16 KB; only first 5,000 term-store terms per tenant used by search — [Microsoft Learn: SharePoint search limits](https://learn.microsoft.com/en-us/sharepoint/search-limits)
- SharePoint Online does not let admins create new refinable/sortable managed properties; you must map to the pre-created RefinableString00–219, RefinableDate, RefinableInt, RefinableDecimal slots, and remapping requires a reindex (secondary sources) — [lookbook365](https://lookbook365.com/features/managed-properties-sharepoint/); [SharePoint Maven](https://sharepointmaven.com/10-limitations-of-crawled-and-managed-properties-in-sharepoint-search-schema/)
- Restricted SharePoint Search (RSS) let admins whitelist up to 100 curated sites for search/Copilot; Microsoft stops new enablements 31 July 2026 and retires it 31 January 2027; replacement is Restricted Content Discovery (RCD) in SharePoint Advanced Management, which works per site with no list limit and has no upgrade path from RSS — [Directions on Microsoft](https://www.directionsonmicrosoft.com/in-brief/restricted-sharepoint-search-retiring-jan-2027/); [Directions on Microsoft report](https://www.directionsonmicrosoft.com/reports/restricted-sharepoint-search-limits-copilot-results/); [MC1427972](https://mc.merill.net/message/MC1427972); [MC726119](https://mc.merill.net/message/MC726119)
- SharePoint Advanced Management features that support Copilot are unlocked for tenants with at least one Microsoft 365 Copilot licence; otherwise the SAM Plan 1 add-on is needed — [Microsoft Learn: SAM licensing](https://learn.microsoft.com/sharepoint/sharepoint-advanced-management-licensing); [SAM features with Copilot licence](https://learn.microsoft.com/en-my/sharePoint/sharepoint-advanced-management-features-copilot-license)
- SharePoint lacks native matter-centricity; firms build matter structure via sites/libraries/metadata; Intapp sells provisioning that applies client-matter metadata to SharePoint sites/Teams (vendor claim) — [fast.io](https://fast.io/resources/sharepoint-for-legal-document-management/); [Intapp](https://www.intapp.com/?p=2274)
- M-Files, Glean and Box all ship Copilot/Graph connectors so their content appears inside Microsoft 365 Copilot — [M-Files Connector for Copilot](https://community.m-files.com/blogs-65091858/b/product-news/posts/m-files-connector-for-microsoft-copilot); [Glean + Microsoft Agent 365](https://www.glean.com/blog/glean-microsoft-integration-2025)

**Azure AI Search ("Foundry IQ (Azure AI Search)")**
- Two pricing/capacity models: Dedicated (size replicas × partitions, tiers Basic, S1–S3/S3 HD, L1–L2) and Serverless (consumption-based, Compute Units per hour + per-GB/month indexed storage; the current preview tier is "Serverless Developer") — [Azure pricing page](https://azure.microsoft.com/en-us/pricing/details/search/); [Microsoft Learn: capacity planning](https://learn.microsoft.com//azure/search/search-capacity-planning); [Microsoft Learn: limits](https://learn.microsoft.com/en-us/azure/search/search-limits-quotas-capacity)
- Agentic retrieval (Foundry IQ knowledge bases) is an add-on charge on both Dedicated and Serverless; separate charges for remote knowledge sources "Microsoft SharePoint (remote)" and "Web"; billing split between Azure OpenAI (query planning/answer synthesis) and Azure AI Search ("Agentic Retrieval 1M tokens" meter) — [Azure pricing page](https://azure.microsoft.com/en-us/pricing/details/search/); [Microsoft Learn: agentic retrieval overview](https://learn.microsoft.com/en-us/Azure/search/agentic-retrieval-overview)
- Serverless cost guidance: keyword search is "low cost", vector search "high cost", hybrid pays for both pipelines; storage charges continue when idle — [Microsoft Learn: serverless cost optimization](https://learn.microsoft.com/en-au/Azure/search/serverless-cost-optimization); [CostBench (third-party)](https://costbench.com/software/enterprise-search/azure-cognitive-search/hidden-costs/)
- Max 4,096 dimensions per vector field on all tiers — [Microsoft Learn: limits](https://learn.microsoft.com/en-gb/azure/search/search-limits-quotas-capacity)
- Connectors: Azure AI Search is an index/retrieval service; ingestion of SharePoint/Exchange/file shares is via indexers (Blob/ADLS, SQL, Cosmos, SharePoint indexer in preview historically) or your own pipeline. No native Exchange mailbox connector was found in this research (gap).

**Google Gemini Enterprise (ex-Agentspace) / Vertex AI (Agent) Search**
- Connectors bring data into dedicated data stores, one per entity type; two modes: federated (data stays in place, no storage charge, lower search quality) and ingested (copied into index, better quality, more storage/time) — [Google Cloud docs: connectors and data stores](https://docs.cloud.google.com/gemini/enterprise/docs/introduction-to-connectors-and-data-stores)
- Data residency: at-rest residency in US and EU multi-regions; ingested and federated connectors "may have limitations in certain multi-regions and in-country regions"; Web Grounding processes ML globally — [Google Cloud docs: locations](https://docs.cloud.google.com/gemini/enterprise/docs/locations)
- Specific connector list for SharePoint/Outlook/OneDrive/Box/file shares was not returned by searches (gap); Google's generic docs reference SharePoint and Outlook connectors existing but I could not confirm feature parity (permission trimming, incremental sync).

### Inferences
- For a firm whose data already sits in Exchange + SharePoint, the lowest-friction permission-trimmed options are Microsoft 365 itself, then Glean or Elastic connectors (both honour source ACLs), then Quick/Q Business. Everything else requires building/maintaining your own connectors and permission mapping.
- On-prem SMB shares are the weak spot across SaaS: the only clearly documented permission-aware option found was Elastic's self-managed Network Drive connector (DLS since 8.11). For Microsoft 365 the path is a Copilot/Graph connector (Microsoft's file-share connector exists historically but its current status was not verified here).
- Copilot Studio's documented inability to filter SharePoint knowledge by column metadata, plus the 25-site cap per agent, is the single most relevant "metadata-rich matter organization" limitation for a law firm building agents on top of SharePoint.

### Gaps
- Could not confirm: Microsoft's native File Share Graph connector status; Azure AI Search SharePoint indexer GA status; Google Gemini Enterprise's exact SharePoint/Outlook connector capabilities (incremental sync, ACL trimming); Quick/Q Business SMB connector; Glean file-share connector; Coveo Exchange/file-system connectors; Vectara's connector/ingestion model; Dropbox Dash and Egnyte connector lists; Carbon.ai status.
- Copilot Retrieval API filter expressions/max results (one third-party source says "up to 25 retrieved documents" per call) were not verified against official docs.

## Key Question 2 — Does ingestion require LLM processing, or can it be limited to extraction, OCR and embedding? Are embeddings exposed/exportable?

### Takeaway
Developer platforms (Azure AI Search, Elastic, Pinecone, Vectara, Ragie, Unstructured, LlamaParse, Bedrock KB) let you choose extraction/OCR/embedding-only pipelines and, except Vectara/Ragie-type managed RAG, store embeddings you can read back. Suite products (Microsoft 365 Copilot semantic index, Gemini Enterprise, Glean, Quick, Box AI, M-Files Aino) index internally and do not expose their embeddings; LLM calls are typically at query time, with optional LLM-based enrichment at ingest (SharePoint Premium autofill, Box Extract agents, M-Files Aino agents) metered separately.

### Cited Findings
- Azure AI Search: "operations included" in a Compute Unit cover searches, indexing, indexer execution and agentic retrieval; AI enrichment, semantic ranker and agentic retrieval are separate optional charges — [Azure pricing](https://azure.microsoft.com/en-us/pricing/details/search/); [CostBench (third-party)](https://costbench.com/software/enterprise-search/azure-cognitive-search/hidden-costs/). Vector fields are first-class index fields (max 4,096 dims) and therefore retrievable via the API — [Microsoft Learn limits](https://learn.microsoft.com/en-gb/azure/search/search-limits-quotas-capacity)
- Gemini Enterprise: ingestion copies data into Google's index; storage billed at about $5/GB-month ("$0.0068 per GiB-hour", first 10 GB free) — embeddings are internal to the data store — [Google Agent Search pricing](https://cloud.google.com/generative-ai-app-builder/pricing); [connectors doc](https://docs.cloud.google.com/gemini/enterprise/docs/introduction-to-connectors-and-data-stores)
- Amazon Q Business index units are sized by "20,000 documents or 200 MB of extracted text, whichever comes first" — i.e. the index is text-extraction-based and capacity-metered, with no exposed vectors — [AWS Q Business pricing](https://aws.amazon.com/q/business/pricing/)
- Bedrock Knowledge Bases (customer-managed) let you pick the vector store (OpenSearch, Aurora PostgreSQL, Neptune, S3 Vectors) so embeddings live in your own store; the newer managed knowledge base is priced at "$5.00 per GB of raw data per month" (third-party reading of AWS pricing page, Oct 2026) — [HackerNoon comparison](https://sia.hackernoon.com/aws-bedrock-knowledge-bases-comparing-s3-vector-store-vs-opensearch-postgresql-and-neptune); [FactualMinds (third-party)](https://www.factualminds.com/blog/bedrock-knowledge-base-cost-optimization-2026/)
- SharePoint Premium / Document Processing for Microsoft 365: autofill columns metered at $0.05 per transaction, one transaction per page processed, billed to a linked Azure subscription — this is optional LLM-style enrichment, separate from search indexing — [Microsoft Learn: Syntex PAYG services](https://learn.microsoft.com/vi-VN/microsoft-365/syntex/syntex-pay-as-you-go-services); [Microsoft Learn: M365 PAYG pricing](https://learn.microsoft.com/en-us/SharePoint/microsoft-365-pay-as-you-go-pricing)
- Microsoft 365 Copilot: prompts, responses and Graph data are not used to train foundation LLMs; the semantic index is Microsoft-internal (not exportable) — [Microsoft Learn: Copilot privacy](https://learn.microsoft.com/DeployOffice/privacy/microsoft-365-copilot)
- Box AI Units are consumed by AI operations (Q&A, extraction); Box AI Extract Agents perform metadata extraction at Enterprise+ — [Box support](https://support.box.com/hc/en-us/articles/43797379758739-Box-AI-Features-in-Business-Plans)
- LlamaParse bills per page in credits that vary by parsing mode (Fast ≈1, Cost-effective ≈3, Agentic ≈10, Agentic Plus ≈45 credits/page per third-party readings) — the non-LLM "Fast" mode is available — [LlamaParse pricing docs](https://developers.llamaindex.ai/llamaparse/general/pricing/); [markaicode (third-party)](https://markaicode.com/pricing/llamaparse-pricing/); [usagepricing (third-party)](https://usagepricing.com/blueprint/activity/llamaindex-2026-07-23-packaging)
- Unstructured: ~15,000 free pages then ≈$0.03/page pay-as-you-go (third-party) — [toolradar](https://toolradar.com/tools/unstructured/pricing); [xpay.sh](https://www.xpay.sh/saas-pricing/unstructured/)
- Embedding APIs: Cohere Embed v4 listed at $0.12 per 1M input tokens on Bedrock/OCI trackers; Cohere's own page reportedly no longer shows per-token prices and lists Embed v5 — [FutureAGI (Bedrock)](https://futureagi.com/llm-cost-calculator/bedrock/cohere-embed-v4-0); [CostBench Cohere](https://costbench.com/software/embedding-apis/cohere-embed/). Voyage AI (acquired by MongoDB for $220M, Feb 2025) keeps its standalone API; voyage-3 series listed at $0.06/$0.02 per 1M tokens with 200M free tokens (third-party archive) — [MongoDB press](https://www.mongodb.com/press/mongodb-strengthens-foundation-for-ai-applications-with-product-innovations-and-expanded-partner-ecosystem); [Bloomberg Law](https://news.bloomberglaw.com/artificial-intelligence/mongodb-buys-voyage-ai-for-220-million-to-bolster-ai-search); [usagepricing (third-party)](https://usagepricing.com/blueprint/activity/voyage-ai-2025-02-24-mongodb-acquisition)
- Pinecone exposes vectors via list/fetch and bulk operations — [Pinecone API docs](https://docs.pinecone.io/reference/api/2026-04/data-plane/list.md)

### Inferences
- A "BYO embeddings" architecture (extract with Unstructured/LlamaParse Fast/Azure Document Intelligence, embed with Voyage/Cohere, store in Azure AI Search, Elastic or Pinecone) keeps ingestion LLM-free and embeddings portable; 100–300 GB of source at the 10–50M-chunk scale would cost in the low hundreds of dollars for embedding at ~$0.06–0.12 per 1M tokens (my estimate: 50M chunks × ~300 tokens ≈ 15B tokens ≈ $900–$1,800 one-off at those rates; re-embedding on model change costs the same again).
- Suite products trade this portability for zero-ops: you cannot export Copilot's semantic index, Gemini Enterprise data stores, Glean's index or Quick's index.

### Gaps
- Vectara's embedding exposure (it uses proprietary Boomerang embeddings; export status not verified here).
- Whether Elastic Serverless charges separately for inference (ML VCUs at ≈$0.07/VCU-hr are listed, but how ELSER/E5 embedding at ingest maps to that was not verified).

## Key Question 3 — Pricing at the firm's scale (100–300 GB source, 10–50M chunks, 20–100 users)

### Takeaway
Per-seat suites cluster at $20–$30/user/month (Microsoft 365 Copilot $30; Gemini Enterprise $21–$35; Quick Professional ≈$20; Glean ≈$45–$75 with 100-seat minimums), so 50 users ≈ $12k–$45k/yr before storage. Infrastructure options scale with data not seats: Azure AI Search S1 ≈ $245/SU-month (third-party), Elastic Hosted from ~$99–$184/month baseline, Gemini/Bedrock managed indexes ≈$5/GB-month (≈$500–$1,500/month for 100–300 GB), Pinecone ≈$0.33/GB-month plus read/write units.

## Key Question 5 — Lock-in and exit: can metadata, extracted text and embeddings be exported?

### Takeaway
Infrastructure layers (Azure AI Search, Elastic, Pinecone, Bedrock KB with your own vector store) store data in indexes you can read back via API, so text, metadata and vectors are exportable. Suite indexes (Copilot semantic index, Gemini Enterprise data stores, Glean, Quick, Box AI, M-Files Aino, Vectara) are internal; your exit asset is the source system (SharePoint/Exchange/M-Files vault) and its metadata, not the AI index.

### Cited Findings
- Pinecone list/fetch API supports paginated enumeration of IDs in serverless indexes; bulk operations exist in the 2026-04 API spec — [Pinecone API docs](https://docs.pinecone.io/reference/api/2026-04/data-plane/list.md)
- Azure AI Search exposes vector fields as index fields with documented dimension limits (retrievable via Search/Lookup APIs) — [Microsoft Learn limits](https://learn.microsoft.com/en-gb/azure/search/search-limits-quotas-capacity)
- Bedrock Knowledge Bases (customer-managed) write embeddings into a vector store you own (OpenSearch, Aurora, Neptune, S3 Vectors) — [HackerNoon comparison](https://sia.hackernoon.com/aws-bedrock-knowledge-bases-comparing-s3-vector-store-vs-opensearch-postgresql-and-neptune)
- Graph connector items are ingested with up to 128 schema properties and remain in the Microsoft index only as citations/search results (no export API found) — [Microsoft Learn](https://learn.microsoft.com/graph/connecting-external-content-api-limits)
- Gemini Enterprise federated mode leaves data in place (nothing to export), ingested mode copies into Google's index — [Google docs](https://docs.cloud.google.com/gemini/enterprise/docs/introduction-to-connectors-and-data-stores)
- M-Files Connector for Copilot "publishes selected information from M-Files to the Microsoft 365 platform" while preserving permissions — the system of record stays M-Files — [M-Files press release](https://www.m-files.com/press-releases/m-files-announces-genai-enhancements-and-m-files-connector-for-copilot-to-increase-end-user-value/)
- Glean reported contract terms: non-removable ~10% support fee, 7–12% annual renewal increases unless capped (third-party competitor sources) — [GoSearch](https://www.gosearch.ai/blog/glean-pricing-explained)

### Inferences
- The lowest lock-in design keeps the canonical metadata in the DMS/SharePoint columns (or M-Files vault) and treats any AI index as rebuildable. If embeddings portability matters, choose Azure AI Search/Elastic/Pinecone with third-party embedding models rather than a suite's internal index.
- Microsoft's semantic index, Gemini data stores and Glean index cannot be exported, but because they index your SharePoint/Exchange in place, exit cost is limited to re-indexing elsewhere.

### Gaps
- No vendor documentation found on exporting Vectara, Ragie, Glean, Quick or Gemini Enterprise indexes; absence of documentation is itself the finding, but it is not a confirmed "no".

## Key Question 7 — Where does a Microsoft-centric firm get the most value with the least new infrastructure, and what are the known limits of Microsoft Search/Copilot for metadata-rich legal matter organization?

### Takeaway
A SharePoint + Exchange firm gets the most value from: (1) fixing SharePoint permissions/oversharing and adopting Restricted Content Discovery (SAM, unlocked by any Copilot licence) before Copilot; (2) Microsoft 365 Copilot ($30/user) which indexes mail, SharePoint and OneDrive with no new infrastructure and includes the Retrieval API for agents; (3) Graph/Copilot connectors (50M items free) for file shares and the DMS; (4) selective SharePoint Premium autofill ($0.05/page) to populate matter metadata. The limits are structural: no native matter model, Copilot Studio cannot filter by SharePoint column metadata, refinable managed properties are fixed slots requiring reindex, RSS whitelist is capped at 100 sites and retires Jan 2027, and semantic index/embeddings are not exportable.

### Cited Findings
- Copilot surfaces only what the user can view; layered law-firm permissions drift; cross-matter exposure is the key risk; an AmLaw 100 deployment relied on matter-level permission audits plus Restricted SharePoint Search (vendor case study) — [Kraft Kennedy](https://www.kraftkennedy.com/copilot-isnt-broken-its-being-literal-monitoring-and-troubleshooting-microsoft-copilot-in-legal/); [copilotconsulting.com case study](https://copilotconsulting.com/case-studies/legal-amlaw-firm); [copilotconsulting.com privilege guide](https://www.copilotconsulting.com/insights/microsoft-copilot-legal-firms-privilege-2026)
- Recommended controls: one site per matter, break inheritance at site level, assign named individuals; RSS described as "the most critical control for law firm Copilot deployments" (vendor) — [copilotconsulting.com safety blueprint](https://www.copilotconsulting.com/insights/copilot-safety-blueprint-legal-privilege-confidentiality); [fast.io](https://fast.io/resources/sharepoint-for-legal-document-management/)
- RSS 100-site cap, retirement 31 Jan 2027, replacement RCD per-site with no list limit — [Directions on Microsoft](https://www.directionsonmicrosoft.com/in-brief/restricted-sharepoint-search-retiring-jan-2027/); [MC1427972](https://mc.merill.net/message/MC1427972)

### Inferences
- Least-new-infrastructure stack for a 20–100-user firm: Copilot licences for knowledge workers + SAM/RCD governance + Graph connector for legacy file shares + SharePoint columns (client/matter/doc-type) mapped to refinable managed properties + optional SharePoint Premium autofill on new intake. Approximate incremental cost at 50 users ≈ $18k–$20k/yr plus metered autofill/credits.
- Where Copilot falls short (structured matter filtering in agents, cross-source metadata facets, exportable embeddings), the natural extension is Azure AI Search/Foundry IQ (hybrid index with your own metadata fields, SharePoint remote knowledge source, agentic retrieval) rather than a third-party suite — it stays in the Microsoft trust boundary and bills to the same Azure subscription. Expect low thousands of dollars/month at this data scale per third-party tier pricing.
- The Jan 2027 RSS retirement means any firm still relying on the 100-site whitelist must move to RCD (per-site) in the next ~3 months.
